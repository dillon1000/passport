## Why this matters

Transactional emails build HTML with template strings. Most links come from
trusted Better Auth URLs, but organization invitation emails include
organization and inviter names controlled by users. Email clients render HTML,
so those names must be escaped before insertion into the HTML body. Plain text
and subjects should keep their current wording; only HTML rendering needs
escaping.

## Steps

### Step 1: Add one HTML escaping helper

In `src/email.ts`, add a small helper near the top of the file:

```ts
function escapeHTML(value: string) {
  return value
    .replaceAll("&", "&amp;")
    .replaceAll("<", "&lt;")
    .replaceAll(">", "&gt;")
    .replaceAll('"', "&quot;")
    .replaceAll("'", "&#39;");
}
```

Use it for every interpolated value inside `html` strings:

- URL text and `href` attributes in magic link, verification, password reset,
  and delete account emails.
- `inviterName`, `organizationName`, and URL in organization invitation HTML.
- The OTP value in the two-factor email, even though it is generated by the
  auth system, so the rule is consistent.

Do not alter the `text` values. Do not alter subjects in this step.

Also bump `package.json` patch version once as required by `AGENTS.md`. If the
version has changed since this plan was written, increment the current patch
version by one instead of hardcoding a target.

**Verify**: `pnpm lint` -> exit 0.

Add tests that call:

Keep the assertions on the captured `EMAIL.send` payload, not on the helper
directly. The public behavior is the sent email payload.

must pass through the escaping helper, while values inserted into plain text do
not need HTML escaping.
