## Why this matters

Passport is meant to be the central place where users sign in to every connected app. The dashboard already has an Applications tab and README copy promises users can revoke app access, but the page currently only shows an empty state. The database schema already contains OAuth clients, consents, access tokens, and refresh tokens, so the product value is close: show users which apps have access and let them revoke that access.

## Steps

### Step 1: Add authenticated application API routes

In `worker/app.ts`, add two custom API routes before the auth route handoff:

- `GET /api/applications`
- `POST /api/applications/:clientId/revoke`

Both must require `getSession`. If no session exists, return `401` with the existing JSON error shape.

Implement listing using Drizzle against `oauth_consent`, `oauth_client`, `oauth_refresh_token`, and optionally `oauth_access_token`. Return only safe fields:

```ts
type AuthorizedApplication = {
	clientId: string;
	name: string;
	icon?: string | null;
	uri?: string | null;
	scopes: string[];
	authorizedAt?: string | null;
	updatedAt?: string | null;
	hasActiveRefreshToken: boolean;
	activeAccessTokenCount: number;
};
```

Rules:

- Filter every query by `session.user.id`.
- Join consents to client metadata by `clientId`.
- Treat refresh tokens with `revoked IS NULL` as active.
- Never return token strings, client secrets, or raw token IDs.
- Sort newest `updatedAt`/`createdAt` first.

For revoke, set `oauth_refresh_token.revoked` to the current timestamp for that `userId` and `clientId`, delete or otherwise invalidate access tokens for that `userId` and `clientId` if the schema and Better Auth behavior make that safe, and remove the matching `oauth_consent` row. If Better Auth exposes an official revoke-consent API in the installed package, use that instead of direct table writes and keep the same route contract.

**Verify**: `pnpm test -- worker/app.test.ts` should compile; existing tests may fail until new tests are added in Step 2, but there should be no TypeScript syntax errors.

### Step 2: Test the API behavior

Extend `worker/app.test.ts` with mocked DB behavior or a small injectable repository abstraction. Follow the existing profile-image tests' pattern: create a fake env, fake session, call `app.fetch`, and assert response shape.

Cover:

- unauthenticated `GET /api/applications` returns `401`
- authenticated list returns app metadata without token or secret fields
- authenticated revoke returns success for a client the user has authorized
- revoke never operates for a different `userId`

If direct Drizzle mocking becomes brittle, introduce a narrow `ApplicationStore` option on `createWorkerApp` for tests, defaulting to the real Drizzle implementation in production.

**Verify**: `pnpm test -- worker/app.test.ts` exits 0.

### Step 3: Replace the Applications empty state with live data

Update `src/pages/Applications.tsx` to:

- fetch `/api/applications` after `useRequireSession()` resolves a user
- show loading skeletons consistent with `src/pages/Sessions.tsx`
- render one row/card per authorized app using `SettingsCard`
- show app name, `clientId`, scopes, and token/activity status
- provide a destructive or outline revoke action with confirmation
- keep the existing empty state only when the API returns an empty list

Use existing UI primitives: `SettingsCard`, `SettingsCardFooter`, `Button`, `Badge`, `Dialog`, `Skeleton`, and lucide icons. Match the restrained dashboard style; do not add marketing copy or large hero UI.

**Verify**: `pnpm lint` exits 0.
